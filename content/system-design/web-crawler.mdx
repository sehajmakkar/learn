## The prompt

A crawler's core loop fits in five lines: take a URL, fetch it, store it, extract links, add the new ones. Every
interesting part of the design is about what that loop does to other people's servers, and to itself, at a billion
pages.

  Design a crawler for a search engine. Starting from a list of seed URLs, it should fetch 1 billion HTML pages a
  month, store them for an indexer, and keep finding new pages through links. It must be polite to every website,
  never fetch the same page twice in one pass, and recrawl pages that change often.

## 1. Requirements

**Functional:** fetch pages from seeds outward; store each page and its metadata; extract and follow links;
recrawl pages based on how often they change.

**Non-functional:**

- **Polite:** one request at a time per host, with a pause between requests, and obey robots.txt.
- **Scalable:** 1 billion pages a month, more by adding machines.
- **Robust:** slow servers, malformed HTML and infinite link structures can't stall it.
- **Restartable:** a crashed node resumes without losing its frontier.

## 2. Estimates

| | Value | What it decides |
| --- | --- | --- |
| Fetch rate | 1 billion ÷ 2.6 million seconds ≈ **400 pages a second** | Asynchronous I/O, thousands of connections |
| Bandwidth | 400 × 100 KB ≈ 40 MB/s, about **320 Mbit/s** | A handful of machines on a good network |
| Storage | 100 TB a month before compression | Object storage, compressed |
| Seen URLs | 10 billion over time | A Bloom filter at 1% is about **12 GB**; exact fingerprints, 80 GB, sharded |
| Hosts in flight | With a 2 s pause per host, 400 pages a second needs **800+ hosts** active at once | The frontier must juggle many hosts |

The last row is the one that shapes the design.

## 4. Deep dives

With one big site (40% of URLs) and a 2-second pause, a single queue with no politeness fetched 594 pages in a
minute, but 510 requests broke the rule, with up to 8 at once on one host. Making each thread wait for its host made
it polite and cut it to **54 pages**, with threads idle 91% of the time. A queue per host fetched **360**, all
polite: the big site got about the same number of requests either way (22 and 21); the difference is that the other threads kept working on
the small sites. With 70% of URLs from one site, even per-host queues left threads idle 70% of the time: politeness
caps each host, so throughput comes from crawling **many hosts at once**.

**robots.txt.** Before fetching from a host, the crawler fetches `/robots.txt` and obeys it. RFC 9309 sets the
rules: cache it for at most 24 hours; if it returns a 4xx, the crawler may fetch anything; if the server errors
(5xx) or can't be reached, assume everything is disallowed; parse at least the first 500 KiB.

  <Option grade="bad" name="Compare URLs as strings">
    `HTTP://Shop.example:80/a#top` and `http://shop.example/a` are the same page; tracking parameters make millions
    of URLs for each page.
  </Option>
  <Option grade="good" name="Normalise, then keep an exact set of seen URLs">
    Correct, but 10 billion URLs is 80 GB of 8-byte fingerprints, which must be sharded or kept on disk.
  </Option>
  <Option grade="great" name="Normalise, check a Bloom filter, and fingerprint the content">
    A Bloom filter (<L id="05.08" />) answers "definitely new" for most URLs in memory; a 1% false positive skips
    a page that will be found again later. A hash of each page's content catches the same page under different URLs
    (mirrors, session IDs), like content addressing in <L id="13.04" />.
  </Option>
</DeepDive>

```ts
const TRACKING = /^(utm_[a-z]+|fbclid|gclid)$/i;

export function normalise(href: string, base?: string): string | null {
  let u: URL;
  try {
    u = new URL(href, base); // resolves relative links against the page
  } catch {
    return null;
  }
  if (u.protocol !== "http:" && u.protocol !== "https:") return null; // mailto:, javascript:, ...
  u.hash = ""; // fragments never reach the server
  u.hostname = u.hostname.toLowerCase().replace(/\.$/, "");
  const params = [...u.searchParams].filter(([k]) => !TRACKING.test(k)).sort(([a], [b]) => a.localeCompare(b));
  u.search = new URLSearchParams(params).toString();
  if (u.pathname === "") u.pathname = "/";
  return u.toString(); // URL already lowercases the scheme and drops default ports
}
```

Tested: `https://Shop.Example:443/a/b/page.html?utm_source=x&b=2&a=1#reviews` became
`https://shop.example/a/b/page.html?a=1&b=2`; `../c?id=7` on that page resolved to `https://shop.example/a/c?id=7`;
`HTTP://shop.example:80` became `http://shop.example/`; `mailto:` and `javascript:` links were dropped; a `gclid`
parameter was removed; and a trailing dot on the host was removed.

<DeepDive title="Splitting the crawl across machines">
  <Option grade="bad" name="Any node takes any URL">
    Politeness then needs a shared, global "last contacted" per host: a hot coordination point for every fetch.
  </Option>
  <Option grade="good" name="A central frontier service">
    One place to enforce politeness, but it becomes the bottleneck and a single point of failure.
  </Option>
  <Option grade="great" name="Partition by host: hash(host) picks the node">
    Each node owns a share of hosts and runs its own frontier, robots cache and DNS cache. Links to hosts it doesn't
    own are sent in batches to the owning node. Politeness stays local, and nodes are added by moving host ranges
    (<L id="05.03" />).
  </Option>
</DeepDive>

**Traps.** Calendars with a "next month" link forever, session IDs in URLs, and generated pages make infinite URL
spaces. Cap URL length and path depth, cap pages per host per crawl, and lower the priority of hosts whose pages are
mostly near-duplicates.

**Freshness.** Recrawl by observed change rate: a news front page hourly, an old article monthly. Conditional requests
(`If-Modified-Since`, `If-None-Match`) let unchanged pages answer 304 with no body.

## 5. Wrap-up

What breaks first is rarely the fetchers: it's **DNS** (each node needs its own caching resolver), the **seen-URL
set** as it grows, and **complaints**, which is why politeness, a clear user agent and a contact page for site owners
are part of the design.

<Mistakes>
  <ul>
    <li>**One FIFO queue.** Runs of same-host URLs either overload a site or idle the threads.</li>
    <li>**Treating a robots.txt error as permission.** A 5xx means assume everything is disallowed.</li>
    <li>**No URL normalisation.** The same page gets crawled under hundreds of URLs.</li>
    <li>**No trap defences.** Cap depth, URL length and pages per host.</li>
  </ul>
</Mistakes>
