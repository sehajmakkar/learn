A new contributor clones the repo and runs one command. Done means:

## Seeding with init scripts

The official Postgres image runs any `.sql` or `.sh` file it finds in `/docker-entrypoint-initdb.d/`, **once**, when it
creates a new database in an empty data directory. Mount a seed file there:

<Code lang="sql" file="db/seed.sql">{`
-- Runs once, when Postgres initialises an empty data volume (see 06.06).
-- The API also creates this table at startup; IF NOT EXISTS keeps the two in agreement.
CREATE TABLE IF NOT EXISTS notes (
  id uuid PRIMARY KEY,
  text text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);

INSERT INTO notes (id, text) VALUES
  (gen_random_uuid(), 'Welcome to the notes API. This note came from db/seed.sql.'),
  (gen_random_uuid(), 'Edit api/src/server.ts while docker compose watch runs, and the API restarts.'),
  (gen_random_uuid(), 'docker compose down keeps these notes. docker compose down -v deletes them.');
`}</Code>

<Code lang="yaml" file="compose.yaml">{`
  db:
    volumes:
      - pgdata:/var/lib/postgresql
      - ./db/seed.sql:/docker-entrypoint-initdb.d/seed.sql:ro
`}</Code>

## What survives what

<Terminal>{`
$ curl -X POST localhost:8080/notes -H 'content-type: application/json' -d '{"text":"added after seeding"}'
$ docker compose down
$ docker compose up -d
$ curl -s localhost:8080/notes | jq length
4
$ docker compose logs db | grep -i initialization
db-1  | PostgreSQL Database directory appears to contain a database; Skipping initialization
$ docker compose down -v
 Volume notes_pgdata Removed
$ docker compose up -d
$ curl -s localhost:8080/notes | jq length
3
$ docker compose logs db | grep initdb
db-1  | /usr/local/bin/docker-entrypoint.sh: running /docker-entrypoint-initdb.d/seed.sql
`}</Terminal>

`down` keeps the volume, so the fourth note survives and the seed doesn't run again. `down -v` deletes it; the next
`up` initialises a fresh database and runs the seed, giving you back exactly three notes. That makes
`docker compose down -v && docker compose up` a one-line "reset my dev data".
