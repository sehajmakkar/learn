## The brief

The notes API is going to production eventually. This step produces its <Term t="image">image</Term>. Done means:

<Recap>
  <ul>
    <li>A `.dockerignore` that keeps `node_modules`, `dist`, `.git` and `.env` out of the build context.</li>
    <li>A multi-stage Dockerfile: TypeScript compiles in one stage, only `dist/` ships.</li>
    <li>Dependencies install in a layer that survives source code changes.</li>
    <li>The container runs as a non-root user and stops in well under a second.</li>
    <li>The image is tagged with a version and the git commit, and pushed to a registry.</li>
  </ul>
</Recap>

Try it yourself first. Each step below has the answer folded away under "Stuck?".

## Step 2: the Dockerfile

<Checkpoint
  title="Write a multi-stage Dockerfile"
  solution={<p>Compare with the finished <code>Dockerfile</code> in <code>project/docker/api</code> (tag <code>docker-step-01</code>). The key moves: name the first stage <code>AS build</code>; copy <code>package.json</code> and the lockfile before <code>npm ci</code>; in the final stage run <code>npm ci --omit=dev</code>, <code>COPY --from=build /app/dist ./dist</code>, then <code>USER node</code> and an exec-form <code>CMD</code>.</p>}
>
  <p>Two stages on <code>node:22-slim</code>. The build stage installs everything and runs <code>npm run build</code>. The final stage sets <code>NODE_ENV=production</code>, installs production dependencies only, copies <code>dist</code> from the build stage, switches to the <code>node</code> user and starts <code>node dist/server.js</code>.</p>
</Checkpoint>

Output trimmed; your ID will differ. No `src`, no `tsconfig.json`, no TypeScript compiler.

Now prove the cache works: change a message in `src/server.ts` and rebuild. Both `npm ci` steps should say `CACHED`;
only the source copy, the compile and the final `COPY --from` should run.

## Step 4: run it like production would

<Terminal>{`
$ docker run -d --name notes -p 8080:3000 notes-api
$ curl localhost:8080/healthz
{"status":"ok"}
$ docker exec notes whoami
node
$ docker stop notes
notes
$ docker logs notes
notes-api listening on :3000
SIGTERM received, closing
`}</Terminal>

`docker stop` returns almost immediately, because the app handles `SIGTERM` and runs as <Term t="pid-1">PID 1</Term> with the exec-form `CMD`. If
yours waits for the whole stop timeout and the logs don't show `SIGTERM received`, check you used `CMD ["node", "dist/server.js"]` and not the shell form.

## Step 5: tag and push

Tag with the version from `package.json` and the short commit hash, so any running <Term t="container">container</Term> can be traced back to
its code:

<Terminal>{`
$ VERSION=$(node -p "require('./package.json').version")
$ SHA=$(git rev-parse --short HEAD)
$ docker run -d --name registry -p 5050:5000 registry:2
$ docker tag notes-api localhost:5050/notes-api:$VERSION
$ docker tag notes-api localhost:5050/notes-api:sha-$SHA
$ docker push --all-tags localhost:5050/notes-api
`}</Terminal>

Both tags point at the same image, so each <Term t="layer">layer</Term> uploads once and the second tag only adds a name. To publish for real, swap
`localhost:5050` for `ghcr.io/YOUR_USERNAME` after `docker login ghcr.io` (<L id="02.06" />).
