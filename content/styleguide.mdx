## Architecture: `<Arch>`

Boxes sit on a grid (`x` is the column, `y` the row). Arrows are `from`/`to` pairs. With `steps`, readers walk a
request through the system; each step's arrows are numbered.

## Sequence: `<Sequence>`

Messages in order, top to bottom. `reply` draws a dashed response, `fail` a lost message, and notes sit over one or
more participants. With `walk`, readers step through one message at a time and see each one's `explain`.

<Sequence
  title="A retry with an idempotency key"
  walk
  participants={[{ id: "c", label: "Client" }, { id: "api", label: "Payments API" }, { id: "db", label: "Database" }]}
  messages={[
    { from: "c", to: "api", label: "POST /charges  key=a1", explain: "The client sends a charge with a key it made up." },
    { from: "api", to: "db", label: "insert key, charge", explain: "The API saves the key and the charge together." },
    { from: "api", to: "c", label: "201 Created", reply: true, fail: true, explain: "The reply is lost on the way back." },
    { note: "client times out", over: ["c"] },
    { from: "c", to: "api", label: "POST /charges  key=a1", explain: "The client retries with the same key." },
    { from: "api", to: "db", label: "find key a1", explain: "The API sees it has handled this key before…" },
    { from: "api", to: "c", label: "201 (saved reply)", reply: true, explain: "…and returns the first answer instead of charging twice." },
  ]}
/>
